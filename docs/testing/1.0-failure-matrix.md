# TelegramJ2ME 1.0 failure matrix

This matrix is the release evidence index, not a list of optimistic claims.
`PASS` requires the evidence named in the row. `NOT RUN` is intentional when
the required environment has not been exercised. A deterministic failure, or a
missing scenario ID, makes `tools/stability-gate.ps1` return a non-zero status.

Allowed statuses are `PASS`, `FAIL`, `NOT RUN`, and `NOT APPLICABLE`.

| AUTH-02 | A silent or failed authorization check does not erase a usable stored session. | deterministic | Exercise timeout, refusal, and cached-session recovery paths. | `api/auth-check`, `app/worker-refusal` | PASS |

## Tested-device evidence boundary

The table deliberately distinguishes “this client has run on the device” from
“this 1.0 RC scenario passed”. Older measurements remain valuable, but do not
turn new rows green.

| Device / environment | Evidence already recorded | 1.0 RC scope | Status |
|---|---|---|---|
| MicroEmulator `live` | Stored production session; earlier navigation work | Full read-only and two-account normal/min E2E | PASS |
| MicroEmulator `bigchats` | Stored production session with large dialog/history sets | Deep history, dialog paging, and two-account normal/min E2E | PASS |
| Nokia C3-00 / 08.70 | Heap, RMS capacity, production session, navigation-key limitation | Upgrade preservation, slow-link search, and manual 1.0 checklist | NOT RUN |
| Samsung GT-C3592 | Historical transport, media, memory, and entropy measurements | No new 1.0 RC claim planned | NOT APPLICABLE |
| Alcatel OT-810D | Historical production, memory, RMS, and entropy measurements | No new 1.0 RC claim planned | NOT APPLICABLE |

Use [device-evidence-template.md](device-evidence-template.md) for every new
hardware result. Evidence must not contain account IDs, usernames, peer titles,
message bodies, auth keys, phone numbers, or route secrets.
